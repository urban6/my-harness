# 계획 세션과 구현 세션 나누기

계획과 구현을 한 세션에서 하지 않는다. 계획 세션은 Claude가 나를 인터뷰해 요구를 확정하고 계획을 파일로 남기는 데까지만 하고, 구현은 그 파일을 읽는 새 세션에서 한다.

## 기준

```text
회원가입 기능 설계해줘.
```

이렇게 바로 설계를 시키면 Claude가 모르는 부분(인증 방식, 중복 처리, 예외 케이스)을 스스로 가정하고 채운다. 그 가정이 계획에 섞여 들어가고, 같은 세션에서 구현까지 이어 가면 탐색·논의 내용이 컨텍스트를 차지한 채로 코드를 쓰게 된다.

```text
회원가입 기능을 만들려고 해. 설계하기 전에 나를 인터뷰해줘.
- 한 번에 질문 하나씩, 선택지가 있으면 같이 제시
- 요구·제약·예외 케이스가 충분히 정해지면 인터뷰를 끝내
- 끝나면 확정된 내용으로 계획을 docs/plans/signup.md에 써줘. 코드는 쓰지 마
```

## 계획 세션에서 할 것

- 인터뷰 먼저: 설계 전에 Claude가 질문하게 한다. 내가 미처 정하지 않은 결정이 이 단계에서 드러난다.
- 코드는 쓰지 않기: 계획 세션의 산출물은 계획 파일 하나다.
- 계획을 파일로 남기기: 구현 세션이 대화 기록 없이 그 파일만 읽고 시작할 수 있게, 확정된 결정과 범위·완료 기준을 적게 한다.

## 구현 세션에서 할 것

새 세션을 열고 계획 파일을 넘긴다. 완료 기준에는 검증 명령을 넣는다([검증까지 요청에 넣기](verify-in-prompt.md)).

```text
docs/plans/signup.md 계획대로 구현해줘.
계획에 없는 결정이 필요하면 멈추고 물어봐.
구현 후 ./gradlew test 통과 확인
```
