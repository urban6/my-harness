# 검증까지 요청에 넣기

구현만 시키지 않는다. 무엇이 맞는 결과인지와 어떻게 확인하는지를 요청에 같이 적어서, 구현 → 검증 → 수정이 한 사이클 안에서 돌게 한다.

## 기준

```text
validateEmail 함수 만들어줘.
```

이렇게만 시키면 "맞게 동작한다"의 기준이 없어서, Claude가 실행해 보지 않고 끝내거나 확인 방법을 스스로 정한다.

```text
validateEmail 함수 작성
테스트 케이스:
- user@example.com -> true
- invalid -> false
- user@.com -> false

구현 후 npm test로 통과 확인
```

## 요청에 넣을 것

- 기대 결과: 입력 → 출력을 구체적인 예로 적는다. 정상 케이스 하나와 실패·경계 케이스 몇 개면 충분하다.
- 확인 방법: 실행할 명령을 적는다(`npm test`, `./gradlew test`, `curl ...`). 이 명령이 통과해야 완료다.
- 실패 시 동작: 통과할 때까지 고치게 할지, 결과를 보고만 받을지 정한다.

## 채워 넣은 예시

API:

```text
POST /users 회원가입 엔드포인트 작성
- 정상 요청 -> 201, Location 헤더
- 이메일 중복 -> 409
- 비밀번호 8자 미만 -> 400

구현 후 ./gradlew test 통과, 실패하면 고치고 다시 실행
```

버그 수정:

```text
주문 취소 시 재고가 복구되지 않는 버그 수정
먼저 이 버그를 재현하는 실패 테스트를 작성하고, 수정 후 그 테스트와 기존 테스트가 모두 통과하는지 확인
```
