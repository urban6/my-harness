# 코드 리뷰

## A — 여러 관점 전체 점검

```text
{대상 범위 — 경로나 최근 변경}를 {커밋 전 / 배포 전}에 점검해줘.

1) architecture-expert로 {레이어·의존성 규칙}이 깨진 곳,
   {경계 밖으로 새면 안 되는 타입}이 노출된 곳을 찾아줘.
2) security-auditor로 인증·인가·민감 데이터 노출을 심각도와 함께 점검.
3) {스킬명} 스킬의 references/{문서}.md 체크리스트로 {점검 항목}을 항목별로.
4) code-reviewer로 가독성·네이밍·에러 핸들링·중복을 마무리 점검.

넷 다 진단만 하고 수정은 하지 마 — 고칠지는 내가 정할게.
발견 항목은 file:line 근거와 함께 심각도 순으로 정리해줘.
```

## B — 관점 하나만 집중

```text
{에이전트}로 {대상 범위}를 점검해줘.
특히 {집중할 항목}을 중점으로 봐줘.

진단만 하고 수정은 하지 마.
발견 항목은 file:line 근거와 함께 심각도 순으로 정리해줘.
```

예시:

```text
security-auditor로 src/main/java/com/example/auth 아래를 점검해줘.
특히 토큰 검증 누락, 권한 체크 우회, 로그에 남는 민감 정보를 중점으로 봐줘.

진단만 하고 수정은 하지 마.
발견 항목은 file:line 근거와 함께 심각도 순으로 정리해줘.
```

## C — 기준을 정해 둔 판정

```text
## 대상
{파일·메서드 또는 diff 범위}만 봐줘.

## 기준 (내가 정한 것)
- {지켜야 할 설계·규칙}
- {지켜야 할 설계·규칙}

## 제외
- {보지 않을 것}

## 출력
- 기준별 PASS / FAIL과 file:line 근거
- FAIL은 최소 수정안만 제시하고, 코드는 고치지 마.
```

예시:

```text
## 대상
OrderService.reserveSeat()와 그 테스트만 봐줘.

## 기준 (내가 정한 것)
- Redis SETNX + TTL 180초로 선점한다
- 선점 성공 시 토큰을 반환하고, 실패 시 SeatAlreadyHeldException을 던진다
- 락 해제는 Lua 스크립트로 본인 토큰일 때만 한다
- 이 메서드에서 DB에 쓰지 않는다
- 동시 요청 100개 중 정확히 1개만 성공하는 테스트가 있다

## 제외
- 네이밍·포맷 같은 스타일

## 출력
- 기준별 PASS / FAIL과 file:line 근거
- FAIL은 최소 수정안만 제시하고, 코드는 고치지 마.
```
