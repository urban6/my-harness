## 특이사항 · 관찰 (테스트로 고정하지 않은 해석 의존 항목)
- `GET /api/coupons/A%00B`: 미리 인코딩된 URI 로 NUL 을 실제 전송하면 **Tomcat 이 앱 도달 전에 400(HTML 오류 페이지, problem+json 아님)으로 거부**한다. 500 은 아니다. `BoundaryFixRegressionTest` 기대값을 400 + non-5xx 로 맞췄다. `GET /api/orders?userId=%00` 은 앱에 도달해 200 빈 페이지다(기대대로).
- `status` 가 PAID 인 totalPrice=0 주문 취소: 구현은 PG 환불을 호출하지 않고 바로 REFUNDED 로 만든다(결제 자체가 PG 를 안 탔으므로). R7.3 문면("PAID → PG에 환불을 요청")과의 해석 차이는 요구사항 확정 필요. 테스트로 고정하지 않음.
- `name` 길이 검사는 UTF-16 코드 유닛 기준이라 이모지 60자(코드포인트 60)도 400 이다. "100자"가 코드포인트 기준이면 불일치. 고정하지 않음.
- `name` 이 NBSP(U+00A0)·전각 공백(U+3000)뿐이어도 201 로 저장된다(`@NotBlank` 는 공백 판정이 `trim()` 기준). "공백만 불가"를 유니코드 공백까지로 해석하면 불일치. 고정하지 않음.
- `quantity` 가 JSON 문자열 `"2"` 이면 숫자로 강제 변환되어 201 이다(`1.5` 는 400). 명세에 정의 없음.
- 만료 스위퍼는 컨텍스트가 캐시된 다른 설정(기본 TTL) 컨텍스트에서도 같은 DB 로 돌지만, SKIP LOCKED 로 이중 복원이 없음을 R6 클래스가 간접 확인한다.
