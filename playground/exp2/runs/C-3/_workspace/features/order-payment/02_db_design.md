# 02. DB 설계: order-payment

- DB는 PostgreSQL(테스트는 Testcontainers `postgres:16-alpine`)이고, 마이그레이션은 Flyway, ORM은 Hibernate 6(`ddl-auto: validate`)이다.
- API 설계: [01_api_design.md](./01_api_design.md)
- **응답 필드 ↔ 컬럼 대응표, 제약 ↔ HTTP 상태·code 매핑표는 [01_api_design.md §16 정합 요약](./01_api_design.md#16-정합-요약-구현검증-기준)만을 기준으로 한다.** 이 문서는 그 표를 복제하지 않는다.

---

## 1. 타입 규약

| 대상 | DB 타입 | Java | 근거 |
|---|---|---|---|
| PK | `bigint GENERATED BY DEFAULT AS IDENTITY` | `Long`, `@GeneratedValue(strategy = IDENTITY)` | R9 keyset 동률 깨기, 단조 증가 |
| 금액 (C1) | `bigint` | `long` / `Long` | int 범위를 넘을 수 있음 |
| 수량(상품 재고·예약, 주문 수량) | `integer` | `int` | 입력 상한 1,000,000 / 1,000 |
| 쿠폰 수량(`total_quantity`, `used_count`) | `bigint` | `long` | 상한이 정의되지 않음. 정상 입력이 int 오버플로로 400이 되는 일을 방지 |
| 시각 (C2) | `timestamptz` | `Instant` (앱에서 **마이크로초 절사** 후 저장) | 정밀도 일치(R9 커서) |
| enum | `varchar` + `CHECK` | `@Enumerated(EnumType.STRING)` | |
| 해시 | `varchar(64)` | `String` | `char(n)`은 Hibernate validate에서 타입이 맞지 않으므로 쓰지 않는다 |

- `smallint`와 `char`는 쓰지 않는다. `ddl-auto: validate`에서 `Integer`/`String`과 타입 코드가 어긋난다.
- 엔티티에 매핑하지 않은 컬럼(`products.created_at`, `coupons.created_at`)은 validate 대상이 아니다. 모두 `DEFAULT now()`로 채운다.
- `idempotency_keys`는 엔티티 없이 `JdbcTemplate`으로만 접근한다.

## 2. 테이블

### 2.1 `products`
| 컬럼 | 타입 | NULL | 기본 | 설명 |
|---|---|---|---|---|
| `id` | bigint identity | N | | PK |
| `name` | varchar(100) | N | | 상품명. 앱에서 `@NotBlank @Size(max=100)` |
| `price` | bigint | N | | 1~10,000,000 |
| `stock` | integer | N | | 판매되지 않은 보유 수량 |
| `reserved` | integer | N | 0 | 결제 대기 주문의 예약 수량 |
| `created_at` | timestamptz | N | now() | 감사용, 엔티티 매핑 생략 가능 |

제약:
- `ck_products_price`: `CHECK (price BETWEEN 1 AND 10000000)`
- `ck_products_stock`: `CHECK (stock >= 0)`
- `ck_products_reserved`: `CHECK (reserved >= 0 AND reserved <= stock)`. 초과 예약이나 음수 재고에 대한 최후 방어선이다.

### 2.2 `coupons`
| 컬럼 | 타입 | NULL | 기본 | 설명 |
|---|---|---|---|---|
| `id` | bigint identity | N | | PK (미노출) |
| `code` | varchar(20) | N | | 대문자·숫자 4~20자. 자연 키이며 UNIQUE |
| `type` | varchar(10) | N | | `FIXED` \| `RATE` |
| `value` | bigint | N | | FIXED는 금액(≥1), RATE는 1~100(%) |
| `min_order_amount` | bigint | N | 0 | |
| `max_discount_amount` | bigint | Y | | null이면 상한 없음 |
| `total_quantity` | bigint | N | | ≥1 |
| `used_count` | bigint | N | 0 | 사용 중(활성) 주문 수 |
| `valid_from` | timestamptz | N | | 포함 |
| `valid_until` | timestamptz | N | | 미포함 |
| `created_at` | timestamptz | N | now() | 매핑 생략 가능 |

제약:
- `uq_coupons_code`: `UNIQUE (code)`. 위반하면 409 `DUPLICATE_COUPON_CODE`. `orders.coupon_code` FK의 참조 대상이기도 하다.
- `ck_coupons_type`: `CHECK (type IN ('FIXED','RATE'))`
- `ck_coupons_value`: `CHECK (value >= 1 AND (type <> 'RATE' OR value <= 100))`
- `ck_coupons_min_order`: `CHECK (min_order_amount >= 0)`
- `ck_coupons_max_discount`: `CHECK (max_discount_amount IS NULL OR max_discount_amount >= 1)`
- `ck_coupons_total_quantity`: `CHECK (total_quantity >= 1)`
- `ck_coupons_used_count`: `CHECK (used_count >= 0 AND used_count <= total_quantity)`. 쿠폰 초과 사용에 대한 최후 방어선이다.
- `ck_coupons_validity`: `CHECK (valid_from < valid_until)`

### 2.3 `orders`
| 컬럼 | 타입 | NULL | 기본 | 설명 |
|---|---|---|---|---|
| `id` | bigint identity | N | | PK. 커서의 두 번째 키 |
| `user_id` | varchar(50) | N | | `X-User-Id` |
| `status` | varchar(20) | N | | 공개 상태 8개 값만 사용. 내부 상태(PAYING 등)는 없다 |
| `coupon_code` | varchar(20) | Y | | FK → `coupons(code)` |
| `subtotal` | bigint | N | | |
| `discount` | bigint | N | | |
| `total_price` | bigint | N | | `subtotal - discount` |
| `payment_id` | varchar(255) | Y | | PG paymentId (환불용, 미노출). total=0 결제는 null |
| `created_at` | timestamptz | N | | 앱이 마이크로초 절사 값으로 설정. 커서의 첫 번째 키 |
| `expires_at` | timestamptz | N | | `created_at + ORDER_PAYMENT_TTL` |
| `paid_at` | timestamptz | Y | | 결제 승인 시각. REFUNDED 이후에도 유지 |

제약:
- `ck_orders_status`: `CHECK (status IN ('PENDING_PAYMENT','PAID','SHIPPED','DELIVERED','PAYMENT_FAILED','EXPIRED','CANCELLED','REFUNDED'))`
- `ck_orders_amounts`: `CHECK (subtotal >= 0 AND discount >= 0 AND discount <= subtotal AND total_price = subtotal - discount)`
- `ck_orders_expires`: `CHECK (expires_at >= created_at)`
- `fk_orders_coupon`: `FOREIGN KEY (coupon_code) REFERENCES coupons(code)`
- **`ux_orders_active_user_coupon`**: `UNIQUE (user_id, coupon_code) WHERE coupon_code IS NOT NULL AND status IN ('PENDING_PAYMENT','PAID','SHIPPED','DELIVERED')`
  - R2.5와 R10.3을 DB에서 보장하는 부분 유니크 인덱스다. 위반하면 409 `COUPON_NOT_APPLICABLE`.
  - 주문이 `CANCELLED`, `EXPIRED`, `PAYMENT_FAILED`, `REFUNDED`로 바뀌면 인덱스 대상에서 빠진다. 그래서 같은 사용자가 그 쿠폰을 다시 쓸 수 있다(R2.6).

인덱스:
| 이름 | 정의 | 용도 |
|---|---|---|
| `ix_orders_created` | `(created_at DESC, id DESC)` | 필터 없는 목록과 keyset |
| `ix_orders_user_created` | `(user_id, created_at DESC, id DESC)` | `userId` 필터 목록 |
| `ix_orders_status_created` | `(status, created_at DESC, id DESC)` | `status` 필터 목록 |
| `ix_orders_pending_expires` | `(expires_at) WHERE status = 'PENDING_PAYMENT'` | 만료 스위퍼 |
| `ux_orders_active_user_coupon` | 위 부분 유니크 | R10.3, 그리고 생성 ⑤d의 EXISTS 조회도 이 인덱스를 탄다 |
| `ix_orders_coupon_code` | `(coupon_code)` | FK 참조 |

### 2.4 `order_items`
| 컬럼 | 타입 | NULL | 설명 |
|---|---|---|---|
| `id` | bigint identity | N | PK |
| `order_id` | bigint | N | FK → `orders(id)` |
| `line_no` | integer | N | 요청 items 순서(0부터). 응답 정렬 기준 |
| `product_id` | bigint | N | FK → `products(id)` |
| `quantity` | integer | N | 1~1,000 |
| `unit_price` | bigint | N | 주문 시점 `products.price` 스냅샷 |

제약과 인덱스:
- `fk_order_items_order`, `fk_order_items_product`
- `uq_order_items_order_product`: `UNIQUE (order_id, product_id)`. 같은 productId 중복 방지(R3.2)이며, 앱의 400 검증이 먼저 걸린다.
- `uq_order_items_order_line`: `UNIQUE (order_id, line_no)`
- `ck_order_items_quantity`: `CHECK (quantity BETWEEN 1 AND 1000)`
- `ck_order_items_unit_price`: `CHECK (unit_price >= 1)`
- `ix_order_items_product`: `(product_id)`. FK 참조용
- `(order_id)` 조회는 `uq_order_items_order_product`의 선두 컬럼으로 처리한다.

### 2.5 `idempotency_keys`
| 컬럼 | 타입 | NULL | 설명 |
|---|---|---|---|
| `id` | bigint identity | N | PK (`begin`이 `RETURNING id`로 반환) |
| `scope` | varchar(20) | N | `ORDER_CREATE` \| `ORDER_PAY`. 두 키 공간을 분리(R4.1) |
| `idem_key` | varchar(64) | N | 클라이언트 `Idempotency-Key` |
| `request_hash` | varchar(64) | N | SHA-256 hex. 입력은 scope, X-User-Id, 메서드와 경로(결제는 order id 포함), 정규화 본문(01 §5.3) |
| `status` | varchar(20) | N | `IN_PROGRESS` \| `COMPLETED` |
| `response_status` | integer | Y | COMPLETED일 때 201 또는 200 |
| `response_body` | text | Y | COMPLETED일 때 응답 JSON 원문 |
| `response_location` | varchar(255) | Y | 주문 생성의 `Location`. 결제는 null |
| `created_at` | timestamptz | N | DEFAULT now() |
| `completed_at` | timestamptz | Y | |

제약:
- `uq_idempotency_scope_key`: `UNIQUE (scope, idem_key)`. `INSERT ... ON CONFLICT (scope, idem_key) DO NOTHING`의 충돌 대상이다.
- `ck_idempotency_scope`, `ck_idempotency_status`
- `ck_idempotency_completed`: `CHECK (status <> 'COMPLETED' OR (response_status IS NOT NULL AND response_body IS NOT NULL))`
- 비2xx로 끝나면 행을 **삭제**한다(R4.4). 만료나 청소는 없다(범위 밖).

## 3. 원자 연산 SQL (구현자가 그대로 사용)

리포지토리에 `@Modifying @Query(nativeQuery = true)`(SELECT 계열은 `@Query(nativeQuery = true)`)로 선언한다. 반환 `int`는 영향을 받은 행 수다. 모든 호출은 서비스의 `@Transactional` 안에서 일어난다.

```sql
-- ProductRepository
-- tryReserve: 0이면 409 INSUFFICIENT_STOCK
UPDATE products SET reserved = reserved + :qty WHERE id = :id AND stock - reserved >= :qty;
-- releaseReservation: 거절·만료·취소
UPDATE products SET reserved = reserved - :qty WHERE id = :id;
-- commitReservation: 결제 승인
UPDATE products SET stock = stock - :qty, reserved = reserved - :qty WHERE id = :id;
-- restock: 환불
UPDATE products SET stock = stock + :qty WHERE id = :id;

-- CouponRepository
-- lockById: 쿠폰 행 잠금
SELECT id FROM coupons WHERE id = :id FOR NO KEY UPDATE;
-- tryUse: 0이면 409 COUPON_EXHAUSTED
UPDATE coupons SET used_count = used_count + 1 WHERE id = :id AND used_count < total_quantity;
-- releaseUse: 복원
UPDATE coupons SET used_count = used_count - 1 WHERE code = :code AND used_count > 0;

-- OrderRepository
-- existsActiveCouponUsage
SELECT EXISTS (SELECT 1 FROM orders
                WHERE user_id = :userId AND coupon_code = :code
                  AND status IN ('PENDING_PAYMENT','PAID','SHIPPED','DELIVERED'));
-- findExpiredIds (스위퍼)
SELECT id FROM orders
 WHERE status = 'PENDING_PAYMENT' AND expires_at <= :now
 ORDER BY expires_at LIMIT :limit;
-- lockExpiredForSweep → Optional<Order>
SELECT * FROM orders
 WHERE id = :id AND status = 'PENDING_PAYMENT' AND expires_at <= :now
 FOR UPDATE SKIP LOCKED;
```
JPQL로는 `findByIdForUpdate`가 있다. `@Lock(LockModeType.PESSIMISTIC_WRITE) @Query("select o from Order o where o.id = :id")`로 선언하며 `SELECT ... FOR UPDATE`가 된다. 결제, 취소, ship, deliver에서 쓴다.

**잠금 순서(전 경로 공통)**: `orders 행` → `products(id 오름차순)` → `coupons 행`. 주문 생성은 기존 주문 행을 잠그지 않으므로 `products(오름차순)` → `coupons`만 쓴다. 상세 근거는 01 §6과 §14에 있다.

멱등 저장소 SQL(`IdempotencyStore`, JdbcTemplate):
```sql
-- begin (REQUIRES_NEW, 즉시 커밋)
INSERT INTO idempotency_keys (scope, idem_key, request_hash, status)
VALUES (?, ?, ?, 'IN_PROGRESS')
ON CONFLICT (scope, idem_key) DO NOTHING
RETURNING id;
-- 충돌 시 조회
SELECT id, request_hash, status, response_status, response_body, response_location
  FROM idempotency_keys WHERE scope = ? AND idem_key = ?;
-- complete (비즈니스 트랜잭션 안)
UPDATE idempotency_keys
   SET status = 'COMPLETED', response_status = ?, response_body = ?, response_location = ?, completed_at = now()
 WHERE id = ? AND status = 'IN_PROGRESS';
-- release (비즈니스 트랜잭션 종료 후, REQUIRES_NEW)
DELETE FROM idempotency_keys WHERE id = ? AND status = 'IN_PROGRESS';
```
`INSERT ... RETURNING`은 `jdbcTemplate.query(sql, (rs, i) -> rs.getLong(1), args)`로 실행한다. 충돌하면 빈 리스트가 반환된다.

## 4. JPA 매핑 지침

- `Product`
  - `@Table(name = "products")`
  - `stock`, `reserved`는 `@Column(nullable = false, updatable = false)`로 둔다. 갱신은 §3의 네이티브 UPDATE로만 한다. 더티 체킹이 벌크 갱신을 덮어쓰는 것을 원천 차단하기 위해서다.
  - 생성자에서 `reserved = 0`으로 설정한다.
- `Coupon`
  - `@Table(name = "coupons")`
  - `type`은 `@Enumerated(STRING)`
  - `usedCount`는 `@Column(nullable = false, updatable = false)`, 생성 시 0
  - `minOrderAmount`는 null이면 0으로 바꿔 저장한다.
- `Order`
  - `@Table(name = "orders")`
  - `status`는 `@Enumerated(STRING)`로 갱신 가능하다.
  - `items`는 `@OneToMany(mappedBy = "order", cascade = CascadeType.PERSIST) @OrderBy("lineNo ASC") List<OrderItem>`
  - 상태 전이 메서드(`markPaid(paymentId, paidAt)`, `markPaymentFailed(paymentId)`, `cancel()`, `refund()`, `expire()`, `ship()`, `deliver()`)를 엔티티에 둔다.
- `OrderItem`
  - `@Table(name = "order_items")`
  - `@ManyToOne(fetch = LAZY) @JoinColumn(name = "order_id") Order order`
  - `productId`는 연관 없이 `Long` 컬럼이다.
- `OrderStatus` enum의 8개 값은 `ck_orders_status`와 정확히 같아야 한다.
- 시각 필드는 `Instant`이고, 설정 전에 `truncatedTo(ChronoUnit.MICROS)`를 적용한다.
- `spring.jpa.open-in-view: false`, `hibernate.default_batch_fetch_size: 100`을 설정한다(01 §13).
- 동시성 제어는 행 잠금과 조건부 UPDATE로 하므로 낙관적 락(`@Version`)은 쓰지 않는다.

## 5. Flyway 마이그레이션

파일: **`src/main/resources/db/migration/V1__init.sql`**

기존 `.gitkeep`과 같은 디렉터리이며 Flyway 기본 `classpath:db/migration` 위치다.

```sql
-- V1__init.sql : order-payment 초기 스키마

CREATE TABLE products (
    id          bigint       GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name        varchar(100) NOT NULL,
    price       bigint       NOT NULL,
    stock       integer      NOT NULL,
    reserved    integer      NOT NULL DEFAULT 0,
    created_at  timestamptz  NOT NULL DEFAULT now(),
    CONSTRAINT ck_products_price    CHECK (price BETWEEN 1 AND 10000000),
    CONSTRAINT ck_products_stock    CHECK (stock >= 0),
    CONSTRAINT ck_products_reserved CHECK (reserved >= 0 AND reserved <= stock)
);

CREATE TABLE coupons (
    id                   bigint      GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    code                 varchar(20) NOT NULL,
    type                 varchar(10) NOT NULL,
    value                bigint      NOT NULL,
    min_order_amount     bigint      NOT NULL DEFAULT 0,
    max_discount_amount  bigint,
    total_quantity       bigint      NOT NULL,
    used_count           bigint      NOT NULL DEFAULT 0,
    valid_from           timestamptz NOT NULL,
    valid_until          timestamptz NOT NULL,
    created_at           timestamptz NOT NULL DEFAULT now(),
    CONSTRAINT uq_coupons_code           UNIQUE (code),
    CONSTRAINT ck_coupons_type           CHECK (type IN ('FIXED', 'RATE')),
    CONSTRAINT ck_coupons_value          CHECK (value >= 1 AND (type <> 'RATE' OR value <= 100)),
    CONSTRAINT ck_coupons_min_order      CHECK (min_order_amount >= 0),
    CONSTRAINT ck_coupons_max_discount   CHECK (max_discount_amount IS NULL OR max_discount_amount >= 1),
    CONSTRAINT ck_coupons_total_quantity CHECK (total_quantity >= 1),
    CONSTRAINT ck_coupons_used_count     CHECK (used_count >= 0 AND used_count <= total_quantity),
    CONSTRAINT ck_coupons_validity       CHECK (valid_from < valid_until)
);

CREATE TABLE orders (
    id           bigint       GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id      varchar(50)  NOT NULL,
    status       varchar(20)  NOT NULL,
    coupon_code  varchar(20),
    subtotal     bigint       NOT NULL,
    discount     bigint       NOT NULL,
    total_price  bigint       NOT NULL,
    payment_id   varchar(255),
    created_at   timestamptz  NOT NULL,
    expires_at   timestamptz  NOT NULL,
    paid_at      timestamptz,
    CONSTRAINT fk_orders_coupon  FOREIGN KEY (coupon_code) REFERENCES coupons (code),
    CONSTRAINT ck_orders_status  CHECK (status IN ('PENDING_PAYMENT', 'PAID', 'SHIPPED', 'DELIVERED',
                                                   'PAYMENT_FAILED', 'EXPIRED', 'CANCELLED', 'REFUNDED')),
    CONSTRAINT ck_orders_amounts CHECK (subtotal >= 0 AND discount >= 0 AND discount <= subtotal
                                        AND total_price = subtotal - discount),
    CONSTRAINT ck_orders_expires CHECK (expires_at >= created_at)
);

CREATE INDEX ix_orders_created         ON orders (created_at DESC, id DESC);
CREATE INDEX ix_orders_user_created    ON orders (user_id, created_at DESC, id DESC);
CREATE INDEX ix_orders_status_created  ON orders (status, created_at DESC, id DESC);
CREATE INDEX ix_orders_pending_expires ON orders (expires_at) WHERE status = 'PENDING_PAYMENT';
CREATE INDEX ix_orders_coupon_code     ON orders (coupon_code);
CREATE UNIQUE INDEX ux_orders_active_user_coupon
    ON orders (user_id, coupon_code)
    WHERE coupon_code IS NOT NULL
      AND status IN ('PENDING_PAYMENT', 'PAID', 'SHIPPED', 'DELIVERED');

CREATE TABLE order_items (
    id          bigint  GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    order_id    bigint  NOT NULL,
    line_no     integer NOT NULL,
    product_id  bigint  NOT NULL,
    quantity    integer NOT NULL,
    unit_price  bigint  NOT NULL,
    CONSTRAINT fk_order_items_order         FOREIGN KEY (order_id)   REFERENCES orders (id),
    CONSTRAINT fk_order_items_product       FOREIGN KEY (product_id) REFERENCES products (id),
    CONSTRAINT uq_order_items_order_product UNIQUE (order_id, product_id),
    CONSTRAINT uq_order_items_order_line    UNIQUE (order_id, line_no),
    CONSTRAINT ck_order_items_quantity      CHECK (quantity BETWEEN 1 AND 1000),
    CONSTRAINT ck_order_items_unit_price    CHECK (unit_price >= 1)
);

CREATE INDEX ix_order_items_product ON order_items (product_id);

CREATE TABLE idempotency_keys (
    id                 bigint       GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    scope              varchar(20)  NOT NULL,
    idem_key           varchar(64)  NOT NULL,
    request_hash       varchar(64)  NOT NULL,
    status             varchar(20)  NOT NULL,
    response_status    integer,
    response_body      text,
    response_location  varchar(255),
    created_at         timestamptz  NOT NULL DEFAULT now(),
    completed_at       timestamptz,
    CONSTRAINT uq_idempotency_scope_key UNIQUE (scope, idem_key),
    CONSTRAINT ck_idempotency_scope     CHECK (scope IN ('ORDER_CREATE', 'ORDER_PAY')),
    CONSTRAINT ck_idempotency_status    CHECK (status IN ('IN_PROGRESS', 'COMPLETED')),
    CONSTRAINT ck_idempotency_completed CHECK (status <> 'COMPLETED'
                                               OR (response_status IS NOT NULL AND response_body IS NOT NULL))
);
```

- 이후 스키마 변경은 `V2__...sql`부터 새 파일로 추가한다. 적용된 V1은 수정하지 않는다.
- `value`와 `type`은 PostgreSQL의 비예약어이므로 따옴표 없이 컬럼명으로 쓸 수 있다. Hibernate가 생성하는 SQL과도 호환된다.
