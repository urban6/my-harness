# 02 DB 설계 — product (상품 등록·조회)

- DBMS: PostgreSQL (테스트: Testcontainers `postgres:16-alpine`. IDENTITY 컬럼 때문에 PostgreSQL 10 이상 필요)
- 마이그레이션: Flyway (build.gradle에 `flyway-core` + `flyway-database-postgresql` 이미 존재 — Flyway 10+는 PostgreSQL 모듈이 분리돼 있어 둘 다 필요)
- ORM: JPA + Hibernate 6.x, `spring.jpa.hibernate.ddl-auto=validate`
- API 설계: [`01_api_design.md`](./01_api_design.md)
- **필드 ↔ 컬럼 대응표, 제약 ↔ 상태코드 매핑표는 [`01_api_design.md` §5 정합 요약](./01_api_design.md#5-정합-요약-구현검증-기준표)이 단일 기준이다.** 이 문서는 그 표를 복제하지 않는다.

## 1. 엔티티 목록

| 테이블 | 설명 | 범위 |
|---|---|---|
| `products` | 상품 | 이 기능의 유일한 테이블 |

주문·회원 등은 범위 외라 테이블을 만들지 않는다. 연관관계 없음.

## 2. `products` 테이블

| 컬럼 | 타입 | NULL | 기본값/생성 | 제약 | 설명 |
|---|---|---|---|---|---|
| `id` | `BIGINT` | NOT NULL | `GENERATED BY DEFAULT AS IDENTITY` | `pk_products` PRIMARY KEY | 서버 생성 id, 1부터 증가 |
| `name` | `VARCHAR(255)` | NOT NULL | — | `ck_products_name_not_blank` | 상품명. trim 없이 저장 |
| `price` | `BIGINT` | NOT NULL | — | `ck_products_price_positive` (`price > 0`) | 판매가, 원 단위 정수 |
| `stock` | `INTEGER` | NOT NULL | — | `ck_products_stock_non_negative` (`stock >= 0`) | 재고 수량 |

### 결정 근거

- **PK 생성 전략 — `IDENTITY` (`GENERATED BY DEFAULT AS IDENTITY`)**
  - PostgreSQL 표준 IDENTITY 컬럼(`SERIAL`보다 권장). JPA `GenerationType.IDENTITY`와 1:1 대응.
  - `ALWAYS`가 아니라 `BY DEFAULT`: 테스트 픽스처나 수동 데이터 보정 시 id를 명시해 넣을 수 있게 한다. Hibernate IDENTITY는 INSERT에 id를 넣지 않으므로 애플리케이션 동작은 동일.
  - IDENTITY는 Hibernate의 JDBC 배치 INSERT를 막지만, 이 기능은 단건 등록뿐이라 무관. `SEQUENCE` + allocationSize 튜닝은 과설계.
- **`price` = `BIGINT`**: 원 단위 금액이 `INTEGER` 상한(약 21억)을 넘을 수 있다. 정수 원 단위라 `NUMERIC`은 불필요.
- **`stock` = `INTEGER`**: 재고 수량은 `INTEGER` 범위로 충분.
- **`name` = `VARCHAR(255)`**: 요구사항에 길이 제한이 없어 관용 기본값 255를 택하고, API 쪽 `@Size(max = 255)`로 같은 한도를 400으로 막는다(01 §2.1). `TEXT`로 무제한을 허용하는 것보다 입력 상한이 명확하다.
- **name 공백 CHECK — 둔다.** 단 Bean Validation `@NotBlank`보다 **같거나 느슨하게** 정의해, 앱 검증을 통과한 값을 DB가 거부하는 일(→ 500)이 원천적으로 없게 한다.
  - `@NotBlank`는 Java `Character.isWhitespace` 기준. PostgreSQL 정규식 `[[:space:]]`는 로케일/인코딩에 따라 판정이 달라(예: NBSP) 앱보다 엄격해질 위험이 있으므로 쓰지 않는다.
  - 대신 `btrim(name, <ASCII 공백 6종>)`을 쓴다: 공백(0x20), TAB(0x09), LF(0x0A), VT(0x0B), FF(0x0C), CR(0x0D). 이 6종은 모두 Java `isWhitespace`가 true이므로, `@NotBlank`를 통과한 문자열(= isWhitespace가 아닌 문자를 1개 이상 포함)은 btrim 후에도 반드시 비어 있지 않다.
  - 빈 문자열 `''`도 이 CHECK로 거부된다.
- **CHECK 제약 이름을 명시**한다(`ck_<table>_<rule>`). 위반 로그에서 어떤 규칙인지 바로 식별되고, 향후 변경 마이그레이션에서 `DROP CONSTRAINT`가 가능하다.
- **unique 제약 없음**: 요구사항에 name 유일성 규칙이 없다 → 중복 등록 허용.
- **감사 컬럼(`created_at` 등) 없음**: 요구사항·응답에 없다. 필요해지면 후속 마이그레이션(`V2__...`)으로 추가.

### 인덱스

| 인덱스 | 컬럼 | 용도 |
|---|---|---|
| `pk_products` (PK가 자동 생성하는 unique B-tree) | `id` | `GET /api/products/{id}` 단건 조회 |

추가 인덱스 없음 — 이 기능의 유일한 조회 경로는 PK 조회다. 목록·검색(name 등)은 범위 외.

## 3. Flyway 마이그레이션

- 위치: `src/main/resources/db/migration/` (이미 `.gitkeep`으로 존재. Spring Boot Flyway 기본 위치 `classpath:db/migration`)
- 파일명: **`V1__create_products.sql`** (버전 1, 밑줄 두 개)
- 이 파일은 적용 후 **수정하지 않는다**(체크섬 불일치로 기동 실패). 변경은 `V2__...`로.

```sql
-- V1__create_products.sql
-- 상품(Product) 테이블. 필드 ↔ 컬럼 / 제약 ↔ 상태코드 정합은 01_api_design.md §5 참조.

CREATE TABLE products (
    id     BIGINT       GENERATED BY DEFAULT AS IDENTITY,
    name   VARCHAR(255) NOT NULL,
    price  BIGINT       NOT NULL,
    stock  INTEGER      NOT NULL,

    CONSTRAINT pk_products
        PRIMARY KEY (id),

    -- @NotBlank보다 느슨해야 한다: ASCII 공백 6종(SP, TAB, LF, VT, FF, CR)만 제거 후 비었는지 검사.
    -- 6종 모두 Java Character.isWhitespace == true 이므로 @NotBlank 통과 값은 항상 이 CHECK도 통과.
    CONSTRAINT ck_products_name_not_blank
        CHECK (btrim(name, E' \t\n\x0B\f\r') <> ''),

    CONSTRAINT ck_products_price_positive
        CHECK (price > 0),

    CONSTRAINT ck_products_stock_non_negative
        CHECK (stock >= 0)
);

COMMENT ON TABLE  products       IS '상품';
COMMENT ON COLUMN products.id    IS '상품 id (IDENTITY)';
COMMENT ON COLUMN products.name  IS '상품명 (공백만 불가, trim 없이 저장)';
COMMENT ON COLUMN products.price IS '판매가, 원 단위 정수 (> 0)';
COMMENT ON COLUMN products.stock IS '재고 수량 (>= 0)';
```

참고:
- `E' \t\n\x0B\f\r'`는 PostgreSQL 이스케이프 문자열 리터럴이다(PostgreSQL E-string은 `\v`를 지원하지 않으므로 VT는 `\x0B`로 쓴다). 문자열 안에 `\'`가 없어 Flyway SQL 파서와 충돌하지 않는다.
- 테이블명은 복수형 `products` — 예약어 충돌 회피(`order`와 같은 문제 예방) 및 스킬 예시(`orders`) 관례와 일치.

## 4. JPA 엔티티 매핑 지침 (`ddl-auto=validate` 전제)

스키마의 원천은 **Flyway 마이그레이션**이다. Hibernate는 스키마를 만들지 않고 기동 시 엔티티와 실제 스키마를 대조만 한다(`validate`: 테이블·컬럼 존재와 타입 호환 검사. 길이·nullable·CHECK는 검사하지 않음 — 그래서 아래 애노테이션 값을 마이그레이션과 수동으로 맞춘다).

```java
package com.example.order.product;

import jakarta.persistence.*;

@Entity
@Table(name = "products")
public class Product {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(name = "name", nullable = false, length = 255)
    private String name;

    @Column(name = "price", nullable = false)
    private long price;

    @Column(name = "stock", nullable = false)
    private int stock;

    protected Product() { }                       // JPA 요구

    public Product(String name, long price, int stock) {
        this.name = name;
        this.price = price;
        this.stock = stock;
    }

    public Long getId() { return id; }
    public String getName() { return name; }
    public long getPrice() { return price; }
    public int getStock() { return stock; }
}
```

지침:

| 항목 | 규칙 | 이유 |
|---|---|---|
| 테이블/컬럼명 | `@Table(name = "products")`, `@Column(name = ...)` 명시 | Boot 기본 네이밍(CamelCase→snake_case)과 결과는 같지만, 명시해 마이그레이션과의 대응을 grep 가능하게 |
| `id` | `Long` + `@GeneratedValue(strategy = GenerationType.IDENTITY)` | `BIGINT IDENTITY`와 대응. 영속 전 null이어야 하므로 래퍼 |
| `name` | `String`, `nullable = false, length = 255` | `VARCHAR(255) NOT NULL` |
| `price` | `long`(원시), `nullable = false` | `BIGINT NOT NULL`. NOT NULL 컬럼이라 원시 타입 안전. null 검증은 요청 DTO(`Long` + `@NotNull`)에서 끝남 |
| `stock` | `int`(원시), `nullable = false` | `INTEGER NOT NULL` |
| 타입 대응 (validate 통과 조건) | `Long`/`long`↔`bigint`, `int`↔`integer`, `String`↔`varchar` | 다르면(예: `price`를 `int`로) 기동 시 `SchemaManagementException` |
| setter | 두지 않는다 | 수정은 범위 외. 생성자로만 상태 설정 |
| `equals`/`hashCode` | 정의하지 않는다 | 컬렉션·연관관계 없음. 가변 필드 기반 구현 금지 |
| Bean Validation 애노테이션 | 엔티티에 두지 않는다 | 검증은 요청 DTO(01 §2.1) 한 곳. 엔티티에 두면 Hibernate가 persist 시 다시 검증해 `ConstraintViolationException`(→ 500)이라는 두 번째 경로가 생긴다 |
| 엔티티 노출 | 컨트롤러 요청/응답에 쓰지 않는다 | `CreateProductRequest`/`ProductResponse` record 사용 |

리포지토리: `public interface ProductRepository extends JpaRepository<Product, Long> {}` — 추가 쿼리 메서드 없음(`save`, `findById`만 사용).

서비스 트랜잭션: `create`는 `@Transactional`, `getById`는 `@Transactional(readOnly = true)`. 엔티티 → `ProductResponse` 변환은 트랜잭션 안에서.

## 5. 설정 규약

### 5.1 원칙

- DB 접속 정보는 **Spring 표준 속성** `spring.datasource.url` / `spring.datasource.username` / `spring.datasource.password`로 받는다.
- 실행 시 환경변수로 덮어쓴다 — Spring Boot relaxed binding이 표준 속성에 자동 대응시키므로 **커스텀 플레이스홀더(`${DB_URL}` 등)를 쓰지 않는다.**

| 속성 | 덮어쓰는 환경변수 | yml 기본값 |
|---|---|---|
| `spring.datasource.url` | `SPRING_DATASOURCE_URL` | `jdbc:postgresql://localhost:5432/product` (로컬 개발용) |
| `spring.datasource.username` | `SPRING_DATASOURCE_USERNAME` | `product` (로컬 개발용) |
| `spring.datasource.password` | `SPRING_DATASOURCE_PASSWORD` | **없음** — yml에 키 자체를 두지 않는다(비밀값 하드코딩 금지) |
| `server.port` | `SERVER_PORT` | `8080` |

- 환경변수는 `application.yml`보다 우선순위가 높으므로 위 기본값은 환경변수가 있으면 자동으로 무시된다.
- `${SPRING_DATASOURCE_URL:...}`나 `${PORT:8080}` 같은 플레이스홀더는 **쓰지 않는다** — 불필요하고, 스킬 예시의 `${DB_URL}`/`${PORT}`를 따르면 요구사항의 `SPRING_DATASOURCE_URL`/`SERVER_PORT` 규약과 어긋난다.
- `spring.datasource.password`에 `${DB_PASSWORD}`처럼 기본값 없는 플레이스홀더를 두면 환경변수가 없을 때 플레이스홀더 해석 실패로 기동이 깨진다. 키를 생략하면 `SPRING_DATASOURCE_PASSWORD`만으로 주입된다.

### 5.2 `src/main/resources/application.yml` (전체)

기존 `spring.application.name: order-service`를 유지하고 다음을 추가한다.

```yaml
spring:
  application:
    name: order-service
  datasource:
    url: jdbc:postgresql://localhost:5432/product
    username: product
    # password: 의도적으로 생략 — SPRING_DATASOURCE_PASSWORD 환경변수로 주입
  jpa:
    hibernate:
      ddl-auto: validate          # 스키마는 Flyway가 관리. Hibernate는 대조만
    open-in-view: false           # 지연 로딩 경계를 서비스 트랜잭션으로 강제
  flyway:
    enabled: true                 # 기본값이지만 의도를 명시. locations 기본값 classpath:db/migration
  jackson:
    deserialization:
      accept-float-as-int: false        # "price": 1000.5 → 400 (01 §3.3)
    mapper:
      allow-coercion-of-scalars: false  # "price": "1000" → 400 (01 §3.3)

server:
  port: 8080
```

### 5.3 테스트(Testcontainers) 설정

- 통합 테스트는 `@SpringBootTest` + `@Testcontainers` + `@Container @ServiceConnection static PostgreSQLContainer<?> postgres = new PostgreSQLContainer<>("postgres:16-alpine");`
  - `@ServiceConnection`(Boot 3.1+)이 `spring.datasource.*`를 컨테이너 접속 정보로 대체한다. 테스트에서 `password` 부재는 문제 되지 않는다.
- 테스트에서도 **`ddl-auto=validate`와 Flyway를 그대로 쓴다**(`create-drop`으로 덮어쓰지 않는다). 그래야 `V1__create_products.sql` ↔ `Product` 엔티티 불일치가 테스트 단계에서 기동 실패로 드러나고, DB CHECK 제약도 실제로 존재하는 상태에서 검증된다.
- 테스트용 `application-test.yml`은 필요 없다. 필요해지더라도 datasource 값을 하드코딩하지 않는다.

## 6. 정합 참조

필드 ↔ 컬럼 대응, 요청 필수 여부 ↔ nullable, Bean Validation ↔ CHECK 제약 등가성, 제약 ↔ 상태코드 매핑은 **[01_api_design.md §5](./01_api_design.md#5-정합-요약-구현검증-기준표)** 를 기준으로 한다. 이 문서의 컬럼·제약을 바꾸면 그 표도 함께 갱신한다.
