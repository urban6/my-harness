## 3. C 워커를 Sonnet으로 고정하는 방법

워커 정의의 `model: opus`(feature-pm·designer·verifier)는 `--model`만으로 바뀌지 않는다.

- **1안 (추천)**: C 실행에만 환경 변수 `ANTHROPIC_DEFAULT_OPUS_MODEL=claude-sonnet-5-5` — `opus` 별칭이 Sonnet으로 풀린다. 하네스 자산은 수정하지 않는다.
- 2안 (1안이 안 먹을 때): run 디렉터리 `.claude/agents/`에 `model: sonnet`으로 바꾼 사본을 둔다. 모델 줄 외에는 원본과 동일.
- 어느 쪽이든 run마다 세션 로그 `modelUsage`에 **Sonnet 외 모델이 있으면 폐기**한다(`analyze_session.py`에 검사 추가).

## 4. 실험 조건

| 항목 | 값 |
|---|---|
| 모델 | 세 군 모두 `claude-sonnet-5-5`, effort high |
| 반복 | 군당 3회, 총 9 run. 라운드 순서 `B→C→A` / `C→A→B` / `A→B→C` |
| 상한 | run당 $60 · 240분 (2차와 동일) |
| 격리 | 2차 방식 + **2차 결과물(정답 구현·run)도 읽기 차단** |

예상 비용: 2차 실측(A·B 약 $4, C 약 $11)보다 낮을 것으로 보지만 Sonnet은 시행착오가 늘 수 있어 run당 $2~10 → 9 run 약 $30~60. 실행 시간은 2차와 비슷하거나 길어 약 3~5시간.

## 5. 채점

2차와 동일 — 정확도 = 요구사항별 통과율 평균 × 60, 테스트 품질 = 규칙 커버(n/48) × 20 + 분기 커버리지 × 10, 완료성 = assemble 5 + 자체 test 5. 참고 열도 동일(비용·시간·자체 테스트 수·분기 수·압축·FIX/REDO).

- 추가 참고 열: 인수 테스트 **실패 유형·실패 요구사항** — Sonnet에서 천장이 깨지면 어디서 깨지는지가 핵심 결과다.
